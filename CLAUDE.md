## Project Overview

This is a web-based Distributed System Monitor built with Rust and WebAssembly. It provides a visual interface for managing distributed LLMs and Model Context Protocol (MCP) servers across a network of servers and workstations. The UI represents the network topology as interconnected server islands, where each island contains processes (shown as buildings) and network connections are visualized as bridges between islands in a star configuration.

## Architecture Overview

### Technology Stack
- **Rust** with `wasm-bindgen` for WebAssembly compilation
- **web-sys** for browser API access
- **HTML5/CSS3** with all styling inline in `index.html`
- **SVG** for map and minimap graphics
- Minimal JavaScript for WASM initialization

### Key Architectural Decisions

1. **Rust-First Architecture**:
   - **ALL application logic in Rust** (`src/lib.rs` - 543 lines)
   - Map state management, viewport controls, event handling
   - Mouse drag/pan, keyboard navigation, coordinate transformations
   - DOM manipulation through web-sys
   - **Minimal JavaScript** (50 lines) - only WASM initialization and event binding
   - HTML/CSS provides complete UI layout (all in `index.html`)

2. **UI Component Structure**:
   - Resource Panel (system-wide metrics: total CPU, memory, network usage)
   - Main Map (SVG-based network topology view)
   - Minimap (overview of entire network with viewport indicator)
   - Server Management Menu (deploy/stop/restart processes)
   - MCP Configuration Menu (server discovery, protocol settings)
   - Alert Console (system notifications and warnings)

3. **Interaction Model**:
   - All event handling in Rust via `#[wasm_bindgen]` functions
   - MapState struct manages viewport position and dimensions
   - Mouse events: drag-to-pan with visual feedback
   - Keyboard events: Arrow keys and WASD for navigation
   - Minimap click: centers viewport on clicked position
   - Status messages displayed in console and footer
   - Thread-local state management for MapState and DragState

### Important Files
- `src/lib.rs`: Main WASM module with all interaction handlers (the only Rust source file)
- `index.html`: Complete UI with inline CSS and JavaScript initialization
- `pkg/`: Generated directory containing WASM binary and JS bindings (after build)
- `scripts/build.sh`: Build automation script
- `scripts/run.sh`: Development server startup script

### System Components

1. **Server Islands**: Each server/workstation is represented as an island containing:
   - Process "buildings" representing running LLMs or MCP servers
   - Resource indicators (CPU, Memory, GPU usage)
   - Connection status indicators

2. **Network Topology**:
   - Star configuration with central routing nodes
   - Bridges between islands represent network connections
   - Connection quality/latency visualization
   - Real-time traffic flow indicators

3. **Monitor Features**:
   - Process deployment and management
   - Resource allocation controls
   - Performance metrics visualization
   - Alert and notification system
   - MCP server discovery and management

### Development Tips
- **Rust-first philosophy**: All new logic should be implemented in Rust, not JavaScript
- The project uses a retro terminal aesthetic (green-on-black theme)
- All styling is inline in `index.html` - no separate CSS files
- The `pkg/` directory is auto-generated by `wasm-pack` and should not be edited manually
- When adding new features:
  - Implement logic in Rust with `#[wasm_bindgen]` export
  - Add tests for new functionality
  - Update JavaScript only if absolutely necessary (event binding)
- State management uses thread-local storage (MAP_STATE, DRAG_STATE)
- DOM manipulation via web-sys (get_element_by_id, set_attribute, etc.)
- Use `./scripts/build.sh` for consistent builds
- Use `./scripts/run.sh` to start the development server (requires `cargo install basic-http-server`)
- Run `cargo test` to verify all tests pass before committing
- Run `cargo clippy` to check for warnings
